# SUJEL.OS — product requirements document

Canonical product document for the GitHub Pages profile at `md-mahfujur-rahman-sujel.github.io`.
`OS-DESIGN-BRIEF.md` remains the Phase 1 visual brief; this document covers the whole product:
the live dashboard, the OS-style shell, the FAQ assistant and the Ironbot mascot.

**Principle:** OS-flavoured, never OS-hidden. Every panel stays visible and readable; the shell adds
polish and speed, not extra clicks. Every number shown is generated from real data or not shown at all.

## 1. Goal and audience

A single static page that works as a portfolio, a live telemetry dashboard and a small piece of
theatre. Audience: recruiters and engineers who land on the GitHub profile or the Pages site.
Secondary audience: the GitHub README, which embeds the same committed SVG panels so both surfaces
always show one identical snapshot (`data/stats.json`).

## 2. Surfaces

| Surface | Width | Shell |
| --- | --- | --- |
| Desktop | 900px and up | Menu bar, window chrome on panels, command palette, clock, Ironbot |
| Phone | under 900px | Existing dock and Explorer sheet, compact Ironbot, no window chrome, no palette trigger |

Both surfaces degrade to a fully readable no-JavaScript page: all content, panels and links render
from committed HTML/SVG; only motion, the palette, the assistant and the Ironbot need scripts.

## 3. Feature requirements

### 3.1 Live dashboard

- Panels: about/identity, projects, stack, telemetry, repositories, activity heatmap, footer sync line.
- Desktop panels are committed SVGs generated by `scripts/render_panels.py` from `data/stats.json`;
  mobile and README render the same snapshot through their own components and embeds.
  Drift between a panel and the snapshot is a bug, caught by `render_panels.py --check`.
- `data/stats.json` is refreshed on a schedule by `.github/workflows/refresh-data.yml` via
  `scripts/generate_stats.py`. A partially available upstream produces an honestly partial snapshot
  and a non-zero exit; CI must not block that update.
- Honesty rules: counts that come from the account API and counts that come from the curated index
  are labelled differently; an empty project description stays empty rather than being invented.

### 3.2 OS shell (Phase 1)

- Palette: dark navy surfaces, one blue accent family (`--accent2`, `--cyan`, `--ice`); red and gold
  belong to the Ironbot art only, never to chrome.
- Window chrome: each desktop panel carries a 24px title bar with three quiet controls.
- Menu bar: brand, section links, Search (Ctrl/Cmd+K), Ironbot toggle, live clock. The clock is
  desktop-only and `aria-hidden`; the visible time is decoration, not content.
- Command palette (`assets/os.css`, `assets/os.js`): ARIA combobox/listbox over sections, projects,
  GitHub, LinkedIn and the Ironbot toggle. Keyboard-first: arrows move, Enter jumps and returns focus
  to the trigger, Escape and backdrop click close. An empty result set withdraws the listbox popup and
  announces "no matches" through a `role="status"` region instead of showing an empty listbox.
- Motion: 120–240ms ease-out transitions; all of it off under `prefers-reduced-motion` and under the
  `html[data-motion="reduced"]` twin, including hover lifts.

### 3.3 FAQ assistant (Phase 2)

- Content contract: `assets/faq.json` holds the display name, greeting, fallback copy, contact links,
  four suggested chips and the Q&A items (13 at present). Each item is `{id, q, k[], a}` where `k` are
  the keywords the matcher uses. Answers that quote live numbers (repository count, current streak)
  are filled from `data/stats.json` at render time, never hard-coded.
- The display name is a single constant in `assets/faq.json`; changing it changes every surface.
- Matching (`assets/assistant.js`): keyword overlap over the question, best score wins, ties keep file
  order. No match returns the fallback copy plus the contact links. A failed `faq.json` fetch says so
  plainly ("could not load") instead of pretending.
- UI: floating action button opening a panel with the transcript, chips and an input. Focus moves to
  the input on open and returns to the button on close; Escape closes.
- Budget: the assistant ships as its own deferred CSS/JS pair (about 5.4 KB JS + 3.4 KB CSS raw) plus
  the 4.7 KB FAQ, none of it on the critical path.

### 3.4 Ironbot (mascot)

- One button (`#flyer-btn`) owns the mascot on both surfaces. Modes: roam, follow (click or toggle),
  drag on touch. `localStorage` key `ironbot` remembers off, with legacy `skybot` migration.
- Power protection: a frame-time watchdog switches the bot off after frames stay above 24ms for three
  seconds (phones are metered); reduced motion disables it entirely; the toggle title explains
  whichever happened.
- Animation: idle bob, tilt and yaw from one rAF tick; a spark burst and spin on mode change; flame
  flicker while running. The mascot is the committed SVG in `index.html`, styled by `assets/site.css`.

## 4. Non-functional requirements

- Performance budgets (`scripts/lighthouse-check.cjs`, mobile): performance ≥ 0.9, accessibility ≥ 0.95,
  best practices ≥ 0.95, LCP ≤ 2500ms, CLS ≤ 0.05. Above-the-fold CSS is inlined by
  `scripts/critical-css.cjs`; the check mode fails CI on drift.
- Payload: nothing heavy on the critical path; every script is deferred.
- Accessibility: zero axe violations on every audited state (page, open palette, open assistant).
  Keyboard parity for palette, assistant, Explorer and the Ironbot toggle.
- Reduced motion: `@media (prefers-reduced-motion: reduce)` and `html[data-motion="reduced"]` twins
  stop every animation and transition, including static hover transforms.
- Privacy: no analytics, no third-party requests at runtime; the only client state is the Ironbot toggle.

## 5. Build and data pipeline

Generated artifacts are committed and verified by drift checks, mirroring the panels:

| Artifact | Generator | Drift check |
| --- | --- | --- |
| `assets/*.svg` panels | `scripts/render_panels.py` | `--check` |
| inlined critical CSS in `index.html` | `scripts/critical-css.cjs` | `npm run test:critical` |
| `data/stats.json` | `scripts/generate_stats.py` (scheduled) | refresh workflow |

## 6. Quality gates

- `python -m unittest discover -s tests -p "test_*.py"` — generator and panel tests.
- `npm test` — Playwright suites (desktop, mobile, OS shell, assistant) including axe audits and
  no-JavaScript assertions.
- `npm run test:critical` — committed-artifact drift.
- `npm run test:performance` — Lighthouse mobile budgets.
- `.github/workflows/validate.yml` runs all of the above on every push and pull request.

## 7. Out of scope

- No backend, no CMS, no build step required to serve: the repository root is the site.
- No server-side assistant; the FAQ matcher is deliberately a keyword table over committed facts.
- No 3D or WebGL mascot: a desktop 3D layer shipped briefly and was removed in November 2026 because
  software-WebGL frame times in CI tripped the Ironbot watchdog and made its test flaky. The SVG art
  is the whole mascot, on every surface.
